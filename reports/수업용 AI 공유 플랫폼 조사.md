# 구독 공유 대신 Max 크레딧으로 수업 AI를 열어라

교수자 한 명의 Claude Pro/Max나 ChatGPT Plus/Pro 계정을 웹사이트 백엔드에 연결해 30~50명이 함께 쓰게 하는 구성은 `claude setup-token`이나 `codex exec`로 기술적으로는 만들 수 있다. 그러나 **Anthropic의 소비자 약관, Claude Code 법률 페이지, 2026년 11월 12일 시행 이용정책과 OpenAI의 이용약관, 계정공유정책, 'Sign in with ChatGPT(SIWC)' 약관이 모두 이를 명시적으로 금지한다.** 사용량 한도도 수업 한 번 안에 바닥날 가능성이 크다. 대신 2026년 10월에 '구독 우선'을 합법적으로 유지하는 길이 생겼다. **Claude Max 5x/20x 구독에 매월 $100/$200의 API 크레딧이 포함되었고**, 이 크레딧은 "자신의 애플리케이션과 에이전트"에 쓸 수 있다. 교수자 API 키로 돌아가는 수업 사이트 비용을 구독료로 미리 내는 셈이다. 학생 40명, 주 2회, 15주 기준으로 비용을 추정하면 Sonnet 5.5 중심의 대화형 수업은 한 학기 약 **$300(₩40만)**, 검색과 실습을 섞은 수업은 약 **$600(₩80만)**이다. 이 정도는 Max 20x 크레딧으로 대부분 감당된다. 매 수업 에이전트 코딩을 시키면 **$1,300~2,600(₩173만~346만)**이 들어 크레딧을 추가로 사야 한다. 학생별 기록 열람은 대학 단위 교육 플랜보다 직접 운영하는 사이트에서 더 쉽다. 기관 플랜의 로그는 IT 관리자의 컴플라이언스·eDiscovery 도구로 묶여 있지만, **Open WebUI는 기본 설정만으로 관리자가 모든 학생 대화를 읽을 수 있다.** 에이전트 기능은 API 키 기반의 Claude Managed Agents나 Agent SDK로 제공하면 된다. 'Claude 웹검색이 GPT보다 약하다'는 우려는 이전 세대 벤치마크와 Claude Code 검색 도구의 설계에서 나온 것으로, 현재는 근거가 약하다. 실제로 남는 위험은 약관보다 개인정보보호법이다. 학생 프롬프트 로그를 쌓는 일과 미국 사업자로의 국외 이전에 대한 고지·동의 절차를 학기 시작 전에 갖춰야 한다.

## 세 개의 문서가 '한 계정, 마흔 명' 릴레이를 막는다

### 설정 토큰 한 줄이면 기술적으로는 돌아간다

질문에 나온 구성 자체는 어렵지 않다. Claude Code의 `claude setup-token`은 브라우저 로그인이 불가능한 "CI 파이프라인, 스크립트" 환경용으로 **유효기간 1년의 OAuth 토큰**을 발급한다. 이 토큰을 `CLAUDE_CODE_OAUTH_TOKEN`에 넣으면 Pro·Max 구독으로 모델 요청을 보낼 수 있다 ([Claude Code 인증 문서](https://code.claude.com/docs/en/authentication)). 서버가 학생 질문마다 `claude -p`를 호출하면 그대로 '구독 백엔드'가 된다. OpenAI도 `codex login`으로 만든 `auth.json`을 신뢰할 수 있는 사설 러너에 두고 `codex exec`를 실행하는 방법을 "고급" 옵션으로 문서화했다 ([Codex CI/CD 인증](https://developers.openai.com/codex/auth/ci-cd-auth)). GitHub에는 이 과정을 포장한 프록시도 많다. `claude-max-api-proxy`는 "Claude Max 구독($200/월)을 OpenAI 호환 API로" 쓰게 해 준다 ([GitHub](https://github.com/sethschnrt/claude-max-api-proxy)). `sub2api`는 아예 '카풀(拼车) 공유'로 구독료를 나누는 기능을 내세우면서 README에서 계정 정지에 대한 책임을 부인한다 ([GitHub](https://github.com/Wei-Shaw/sub2api)). 문제는 이 공식 문서들이 **구독자 본인의 자동화**를 위한 메커니즘을 설명할 뿐이라는 점이다. 다른 사람의 사용을 허락하는 문서가 아니다.

### Anthropic은 구독을 거치는 라우팅을 세 겹으로 금지한다

Anthropic에서는 각각 독립적으로 효력을 갖는 세 문서가 모두 이 구성을 금지한다. 첫째, 2025년 10월 8일 시행 소비자 약관이다. §2는 "계정을 다른 누구에게도 이용 가능하게 해서는 안 된다"고 못 박는다. §3은 API 키가 아닌 봇이나 스크립트로 자동 접근하는 것을 명시적 허락 없이는 금지한다. §12는 위반 시 **예고 없이 접근을 정지하고 남은 구독료는 환불하지 않는다**고 규정한다 ([Anthropic 소비자 약관](https://www.anthropic.com/legal/consumer-terms)). 둘째, Claude Code의 '법률 및 컴플라이언스' 페이지는 더 구체적이다. Anthropic은 개발자가 "사용자를 대신해 Free, Pro, Max 플랜 자격증명으로 요청을 라우팅하는 것"을 허용하지 않는다고 밝힌다. Agent SDK를 쓰는 제품도 API 키 인증을 써야 하고, Pro·Max의 광고된 한도는 "평범한 개인 사용"을 전제한다고 명시한다 ([Claude Code 법률 페이지](https://code.claude.com/docs/en/legal-and-compliance)). 셋째, 2026년 11월 12일 시행 예정인 새 이용정책(AUP)은 "소비자 구독을 경유해 요청을 라우팅하는 서비스"를 포함해 Claude에 대한 무단 재판매·프록시·접근 제공을 금지 항목에 넣었다 ([Anthropic 이용정책](https://www.anthropic.com/legal/aup)).

이 문구들은 특정 '서드파티 하네스'가 아니라 **남을 대신해 요청을 중개하는 행위 자체**를 겨냥한다. 따라서 교수자가 Anthropic 공식 `claude` 바이너리를 그대로 감싸 쓰더라도 예외가 되지 않는다. 같은 법률 페이지가 허용하는 것은 정반대 구조다. 고객이 직접 발급한 API 키를 "고객 자신의 승인된 사용자"가 쓰게 하되, 사용료가 키 소유자에게 청구되고 재판매나 중개가 없어야 한다 ([Claude Code 법률 페이지](https://code.claude.com/docs/en/legal-and-compliance)). 수업 사이트가 합법이 되는 조건은 바로 이 문장에 들어 있다.

### OpenAI는 개인 사용에는 관대해졌지만 타인 요청에는 똑같이 단호하다

OpenAI는 2026년에 Anthropic과 반대 방향으로 움직였다. 9월 29일 DevDay에서 'Sign in with ChatGPT(SIWC)'를 확장해, Plus·Pro 구독자가 OpenCode, OpenClaw 등 **16개 파트너 도구에서 자기 플랜 사용량을 쓸 수 있게** 했다 ([The New Stack](https://thenewstack.io/sign-in-with-chatgpt/)). 그런데 같은 SIWC 약관은 다음 세 가지를 요구하거나 금지한다. 요청은 "해당 사용자의 로컬 런타임이나 그 사용자만 통제하는 원격 런타임"에서 나와야 한다. 한 사용자의 활동이 다른 사용자 계정으로 요청을 일으켜서는 안 된다. "플랜 사용량이나 토큰을 풀링하거나 공유"해서도 안 된다 ([SIWC 약관](https://openai.com/policies/sign-in-with-chatgpt-terms/)). 기본 이용약관도 계정을 타인이 쓰게 하는 것을 금지하고, 계정공유정책은 계정이 그것을 만든 개인을 위한 것이라고 밝힌다 ([OpenAI 이용약관](https://openai.com/policies/row-terms-of-use/); [계정공유정책](https://help.openai.com/en/articles/10471989-openai-account-sharing-policy)). Codex 문서도 ChatGPT 로그인 `auth.json`을 "동시 작업이나 여러 머신에서 공유하지 말라"고 경고한다 ([Codex CI/CD 인증](https://developers.openai.com/codex/auth/ci-cd-auth)). 50명의 동시 요청을 로그인 하나로 흘려보내는 구조가 정확히 이 경고에 해당한다. 다만 OpenAI 페이지는 이번 조사 환경에서 직접 열리지 않았다. 위 문구는 공식 페이지의 검색 발췌로 확인한 것이므로 인용하기 전에 원문과 대조해야 한다.

이 연표에서 읽을 수 있는 점은 하나다. 2026년 내내 Anthropic이 오락가락한 것은 **구독자 본인이** 서드파티 도구를 쓸 때의 과금 문제였다. 4월에는 "구독에서 제외"라고 했고, 10월 도움말은 "서드파티 앱도 구독 한도로 사용 가능"이라고 써서 서로 충돌한다. **타인과의 공유 금지는 한 번도 바뀌지 않았다.** 학생이나 팀원과 계정을 공유했다는 이유만으로 정지된 사례를 다룬 1차 자료는 찾지 못했다. 하지만 1월 사례는 남용 필터가 계정을 자동으로 정지할 수 있음을 보여 준다. 30~50명이 한 학기 동안 계정 하나로 보내는 트래픽은 "평범한 개인 사용"과 거리가 멀다. Anthropic은 이런 조치를 "사전 통지 없이" 취할 수 있다고 밝혔다 ([Claude Code 법률 페이지](https://code.claude.com/docs/en/legal-and-compliance)). 학기 중간에 계정이 정지되면 수업이 멈추고 구독료도 돌려받지 못한다. OpenAI가 공유 계정이나 '카풀' 릴레이를 단속한 데이터는 찾지 못했다. 단속 데이터가 없다는 것이 약관상 허용된다는 뜻은 아니다.

### 약관을 무시해도 5시간 한도가 수업 한 번을 버티지 못한다

용량 문제만 따져도 결론은 같다. Anthropic은 Pro·Max에 "5시간 세션 한도와 주간 한도"가 있다고 밝히지만 구체적인 수치는 공개하지 않는다 ([Claude 도움말](https://support.claude.com/en/articles/11145838-use-claude-code-with-your-pro-or-max-plan)). 2026년 5월 6일에 Claude Code의 5시간 한도를 두 배로 늘렸지만 이때도 절대 수치는 밝히지 않았다 ([Anthropic](https://www.anthropic.com/news/higher-limits-spacex)). Codex Plus는 최상위 모델 기준으로 5시간당 로컬 메시지 약 15~160개로 알려져 있다. Pro는 5시간 한도 없이 비공개 주간 한도만 있다는 2차 자료가 있다 ([Codex 가격](https://developers.openai.com/codex/pricing); [SessionWatcher](https://sessionwatcher.com/guides/codex-rate-limits-explained)). 학생 40명이 75~90분 수업에서 각자 10~20번 질문하면 5시간 창 하나에 400~800건의 요청이 몰린다. ChatGPT Plus라면 몇 분 만에 한도가 끝난다. Max 5x도 `claude -p` 호출 하나하나에 Claude Code의 긴 시스템 프롬프트와 도구 정의가 붙기 때문에 수업 한 번 안에 소진될 공산이 크다. Max 20x나 ChatGPT Pro는 한 차시는 버틸 수 있다. 그래도 주 2~3회 수업에 과제까지 더하면 비공개 주간 한도에 걸릴 위험이 남는다. 무엇보다 다수의 동시 세션이라는 패턴 자체가 1월에 계정 자동 정지를 부른 "비정상 트래픽"과 같은 모양이다. 반면 종량제 API는 한도가 명시되어 있고 상향을 요청할 수도 있어서, 실패하는 방식을 예측할 수 있다.

### 합법적인 '구독 우선' 경로는 Max 구독에 딸린 월 $100~200 API 크레딧이다

2026년 10월부터 **Max 5x는 월 $100, Max 20x는 월 $200의 Claude API 크레딧**을 포함한다. Team 플랜은 Standard 좌석당 $20, Premium 좌석당 $100의 크레딧을 합산해 월 최대 $500까지 준다. 받으려면 Claude Console 조직을 연결하고 프로그램 약관에 동의하면 된다. 문서는 이 크레딧을 "자신의 애플리케이션과 에이전트를 만들고 운영하는 데" 쓸 수 있다고 설명한다. 적용 대상은 Claude API, Managed Agents, Agent SDK, Playground다. **Claude Code와 Claude 앱의 추가 사용량은 대상이 아니다.** 크레딧은 매 결제 주기마다 소멸하고 이월되지 않는다. 다 쓰고 따로 구매한 잔액도 없으면 API 요청이 멈출 뿐, 구독 요금으로 넘어가 청구되지는 않는다. 신규 구독자는 7일을 기다려야 크레딧을 받을 수 있고, Free·Pro·Enterprise 플랜은 대상이 아니다 ([API 크레딧 문서](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers); [Claude 도움말](https://support.claude.com/en/articles/17154008-api-credits-for-max-and-team-plans)). 크레딧은 Claude와 Claude Code의 사용량 한도를 바꾸지 않으므로, 교수자가 개인적으로 쓰는 Max 한도는 그대로 남는다. 배포는 10월 7일 무렵부터 순차적으로 진행 중이라 일부 계정에는 아직 보이지 않을 수 있다 ([developersdigest](https://www.developersdigest.tech/blog/claude-max-team-monthly-api-credits-2026)).

이 크레딧을 앞 절의 법률 페이지 문장과 함께 읽으면 구조가 맞아떨어진다. 교수자의 Console 조직이 발급한 API 키를 교수자 자신의 승인된 사용자인 수강생이 쓰고, 비용은 키 소유자인 교수자에게 청구되며, 재판매는 없다. 이 경우 적용 약관은 소비자 약관에서 상용 약관으로 바뀐다. 따라서 학생에게 이용료를 받으면 안 된다. 또 AUP에 따라 사이트는 최소한 각 대화 시작 시점이나 인터페이스에서 "사람이 아니라 AI와 대화 중"임을 고지해야 한다 ([Anthropic 이용정책](https://www.anthropic.com/legal/aup)). 남은 불확실성은 하나다. 이번 조사에서는 [크레딧 프로그램 약관](https://www.anthropic.com/legal/credit-terms) 원문을 읽지 못했다. 문서 표현으로 보면 여러 사용자가 쓰는 자체 앱도 허용될 가능성이 높지만, 개설 전에 교수자가 직접 확인해야 한다. 교육용 릴레이를 따로 다룬 Anthropic의 공식 입장도 찾지 못했다.

ChatGPT 쪽에는 이런 다리가 없다. Plus나 Pro에 OpenAI API 크레딧이 포함된다는 근거는 찾지 못했다. 그래서 ChatGPT 구독으로는 수업 사이트 비용을 댈 수 없고, 사이트에 GPT 모델을 쓰려면 별도의 종량제 API 결제가 필요하다. SIWC로 학생 각자가 **자기** ChatGPT 플랜을 사이트에 연결하는 방식은 약관과 정합적이다. 하지만 원격 호스팅 앱은 대기자 명단에 올라야 하고, 학생들이 유료 플랜을 갖고 있어야 하므로 "학생에게 구독을 강요하지 않는다"는 전제와 충돌한다 ([SIWC 개발자 문서](https://developers.openai.com/siwc)). 결국 Pro, ChatGPT Plus, ChatGPT Pro 중 어느 것도 수업을 합법적으로 떠받칠 수 없다. **수업에서 쓸 수 있는 가치로 바뀌는 개인 구독은 Max가 유일하다.**

## 에이전트는 API 키 위에서만 여러 학생에게 열린다

Claude Agent SDK(Python `claude-agent-sdk`, TypeScript `@anthropic-ai/claude-agent-sdk`)는 Claude Code의 에이전트 루프를 라이브러리로 제공한다. 파일 읽기·쓰기·편집, Bash, 웹 검색과 페치, 서브에이전트, 훅, MCP, 세션 재개까지 포함된다. 그러나 문서는 "사전 승인이 없는 한 서드파티 개발자가 Agent SDK 기반 에이전트를 포함한 자기 제품에 claude.ai 로그인이나 구독 한도를 제공하는 것을 허용하지 않는다"고 못 박는다. 인증은 API 키나 Bedrock, Google Cloud, Foundry 자격증명으로 해야 한다. 제품 이름은 "Claude Agent"나 "○○ Powered by Claude"로 부를 수 있지만 "Claude Code"라고 부르거나 Claude Code의 외관을 흉내 내면 안 된다 ([Agent SDK 개요](https://code.claude.com/docs/en/agent-sdk/overview)). Max 크레딧이 Agent SDK와 Managed Agents에 쓰일 수 있다는 점은 앞 절의 결론과 그대로 이어진다. 수업용 에이전트도 크레딧으로 운영할 수 있다는 뜻이다.

### Managed Agents는 샌드박스와 전체 로그를 시간당 $0.08에 대신 운영한다

교수자 한 명이 운영하기에 가장 현실적인 선택지는 **Claude Managed Agents**다. 에이전트 루프와 샌드박스를 Anthropic이 호스팅하고, bash·read·write·edit·glob·grep·web_fetch·web_search 도구를 기본으로 제공한다. 실행 결과는 SSE로 스트리밍되며, 문서는 "이벤트 기록이 서버 측에 저장되어 전체를 다시 가져올 수 있다"고 설명한다 ([Managed Agents 개요](https://platform.claude.com/docs/en/managed-agents/overview); [Managed Agents 도구](https://platform.claude.com/docs/en/managed-agents/tools)). 요금은 모델 토큰에 더해 **`running` 상태일 때만 세션 시간당 $0.08**이다. 학생이 생각하느라 멈춰 있는 시간에는 과금되지 않는다. Anthropic이 든 예시를 보면 Opus 5.5로 1시간, 입력 5만·출력 1.5만 토큰을 쓴 세션이 약 $0.58이다 ([Claude 가격](https://platform.claude.com/docs/en/about-claude/pricing)). Agent SDK 호스팅 문서도 "에이전트 루프를 자체 인프라에서 돌릴 필요가 없다면 Managed Agents를 고려하라"고 권한다 ([Agent SDK 호스팅](https://code.claude.com/docs/en/agent-sdk/hosting)). 이 경우 백엔드가 할 일은 네 가지뿐이다. 학생을 인증하고, 학생이나 과제마다 세션을 만들고, SSE를 브라우저로 중계하고, `student_id → session_id` 대응표를 저장하는 것이다. 이렇게 하면 교수자는 학생별 모든 도구 호출과 출력을 다시 볼 수 있다. 학생 40명이 주당 3시간씩 실제로 실행한다고 가정하면 런타임 비용은 주 $10 안팎이다(요금표로 계산한 추정). 단점도 있다. 상태를 저장하는 구조라서 무보존(ZDR) 대상이 아니어서 학생 작업이 Anthropic 쪽에 저장된다. 아직 베타라는 점도 감안해야 한다. 조직 전체 세션을 조회하거나 필터링하는 엔드포인트도 이번 조사에서 확인하지 못했으므로, 대응표는 자체 DB에 두는 편이 안전하다.

### 직접 호스팅하면 학생당 컨테이너와 gVisor가 최소한의 안전선이다

Agent SDK를 직접 호스팅하면 Claude Code에 가장 가까운 경험을 줄 수 있지만 운영 부담이 커진다. `query()`는 세션 하나당 셸과 작업 디렉터리를 가진 `claude` 하위 프로세스를 하나씩 띄운다. 공식 문서가 제시하는 출발점은 **에이전트당 RAM 1GiB, 디스크 5GiB, CPU 1개**다. 최소 사양 컨테이너는 시간당 약 $0.05인데, 긴 에이전트 세션 하나가 토큰으로 몇 달러를 쓴다. 그래서 토큰 비용이 인프라 비용보다 "한 자릿수 이상" 크다 ([Agent SDK 호스팅](https://code.claude.com/docs/en/agent-sdk/hosting)). 문서가 제시하는 멀티테넌트 설정으로는 `settingSources: []`, 테넌트별 `CLAUDE_CONFIG_DIR`, 테넌트별 `cwd`가 있다. 이 설정들은 학생 사이의 맥락이 섞이는 것을 막아 줄 뿐 악성 코드까지 막지는 못한다. 따라서 Bash를 허용한다면 학생마다 컨테이너를 따로 주어야 한다. Anthropic의 보안 배포 문서는 격리 수준을 sandbox-runtime, Docker, gVisor, Firecracker VM 순으로 정리한다. 멀티테넌트 환경이나 신뢰할 수 없는 콘텐츠를 다룰 때는 gVisor의 오버헤드를 감수할 가치가 있다고 하고, API 키는 샌드박스 바깥의 프록시에서 주입하라고 권한다 ([보안 배포](https://code.claude.com/docs/en/agent-sdk/secure-deployment)). 권한 설정에도 함정이 있다. `allowedTools`에 `permissionMode: "dontAsk"`를 조합하는 것이 권장 패턴이다. `bypassPermissions`를 쓰면 `allowed_tools=["Read"]`로 지정해도 Bash와 Write가 그대로 승인된다. 반면 `PreToolUse` 훅의 거부는 bypass 모드에서도 적용된다 ([Agent SDK 권한](https://code.claude.com/docs/en/agent-sdk/permissions)). 관리형 샌드박스를 쓴다면 E2B가 vCPU당 시간당 약 $0.05 수준이다. 무료 Hobby 플랜은 동시 실행 샌드박스가 20개로 제한되므로 30~50명이 함께 하는 실습에는 월 $150의 Pro 플랜이 필요하다 ([E2B 가격](https://www.e2b.dev/pricing)).

### Codex를 원하면 API 키와 `codex exec`, 또는 출시 6주 된 Agents API로 간다

Codex를 쓰는 길은 세 가지다. `codex exec --json`은 이벤트를 JSONL로 스트리밍한다. TypeScript SDK는 CLI를 띄워 이벤트를 주고받는다. Python SDK(`openai-codex`)는 API 키 로그인을 지원한다 ([Codex 비대화형 모드](https://developers.openai.com/codex/noninteractive); [Codex TS SDK](https://github.com/openai/codex/blob/main/sdk/typescript/README.md)). 앱 서버는 "실험적이며 프로덕션 워크로드용이 아니다"라고 명시되어 있고, `codex mcp-server`는 2026년 9월 5일에 제거되었다 ([Codex 앱 서버](https://developers.openai.com/codex/app-server); [Codex MCP 서버 제거](https://developers.openai.com/codex/guides/agents-sdk)). 따라서 수업용으로는 교수자의 OpenAI API 키와 학생별 컨테이너 안의 `codex exec` 조합이 정석이다. 9월 10일에는 Codex 하네스와 호스팅 샌드박스를 API 호출 하나로 묶은 OpenAI **Agents API**가 공개 베타로 출시되었다. Claude Managed Agents에 대응하는 서비스지만, 데이터 보관 지역이 미국뿐이고 ZDR을 지원하지 않는다 ([MarkTechPost](https://www.marktechpost.com/2026/09/10/openai-launches-the-agents-api-in-public-beta-putting-the-codex-harness-behind-one-api-call/); [Agents API FAQ](https://help.openai.com/en/articles/20001551-agents-api-beta-faq)).

이미 나와 있는 'Claude Code 웹 UI' 프로젝트들은 이 용도에 맞지 않는다. 별 14,269개의 CloudCLI(claudecodeui)는 셀프 호스팅 비교표에 "팀 공유: 없음"이라고 적혀 있고, "모든 옵션이 사용자 본인의 AI 구독을 사용한다"고 설명한다 ([claudecodeui](https://github.com/siteboon/claudecodeui)). 학생들에게 열면 바로 약관 위반이 된다. OpenHands(MIT, 별 91,738개)는 대화마다 Docker 컨테이너를 띄우고 Claude Code와 Codex를 구동할 수 있지만, 수강생 명단보다는 개발팀을 위해 만든 도구다 ([OpenHands](https://github.com/OpenHands/OpenHands)). LibreChat의 첨부 작업공간은 "매우 실험적"인 단계다 ([LibreChat](https://github.com/LibreChat-AI/LibreChat)). Open WebUI에서 사용자별 격리 터미널을 쓰려면 엔터프라이즈 기능인 Terminals가 필요하다 ([Open WebUI](https://github.com/open-webui/open-webui)). 정리하면, **다수 사용자 인증과 사용자별 감사 로그를 갖춘 성숙한 오픈소스 'Claude Code 웹' 프로젝트는 아직 없다.** Managed Agents 위에 얇은 앱을 직접 짜는 편이 1인용 UI에 멀티테넌시를 덧붙이는 것보다 쉽다.

기록 남기기는 어느 경로에서든 어렵지 않다. SDK가 내보내는 메시지는 이미 구조화된 JSON이므로, 브라우저로 중계하면서 `events(student_id, session_id, ts, type, payload)` 테이블에 그대로 쌓으면 교수자 대시보드는 이 테이블을 조회하는 화면이 된다. 두 번째 층으로 OpenTelemetry를 쓸 수 있다. `query()`마다 `OTEL_RESOURCE_ATTRIBUTES="enduser.id=…"`를 지정하면 학생별 감사 추적이 된다. 단, 프롬프트 본문은 기본적으로 내보내지 않으므로 `OTEL_LOG_USER_PROMPTS=1`처럼 명시적으로 켜야 한다 ([Agent SDK 관측성](https://code.claude.com/docs/en/agent-sdk/observability)).

### 'Claude 웹검색 열세론'은 이전 세대 벤치마크와 도구 설계에서 나왔다

우려에는 근거가 있었지만 대부분 지난 이야기다. 이전 세대 비교에서는 BrowseComp 점수가 GPT-5.5 84.4%, Claude Opus 4.7 79.3%로 GPT가 앞섰다 ([DataCamp](https://www.datacamp.com/blog/gpt-5-5-vs-claude-opus-4-7)). 2026년 10월 제3자 리더보드는 서로 엇갈린다. TensorFeed는 GPT-6 Astra를 91.5%로 1위에 올렸다 ([TensorFeed](https://tensorfeed.ai/benchmarks/browsecomp)). Mercor의 10월 1일 집계는 GPT-6.1 Sol 95.4%, GPT-6 Astra 94.2%다 ([BenchLM Mercor](https://benchlm.ai/benchmarks/mercorbrowsecomp)). BenchLM은 Claude Opus 5를 93.6%로 기록했고 ([BenchLM](https://benchlm.ai/benchmarks/browsecomp)), 다른 비교에서는 Opus 5가 90.8%로 GPT-5.5 Pro의 90.1%보다 높다 ([llm-stats](https://llm-stats.com/models/compare/claude-opus-5-vs-gpt-5.5)). 이 수치들은 실행 환경이 서로 달라 직접 비교할 수 없다. 전부 90점대 초중반에 몰려 있어서 OpenAI가 약간 앞서는 설정도 있지만 '열세'라고 부를 만한 격차는 아니다. Anthropic은 Opus 5.5 발표에서 BrowseComp 대신 도구 사용 Humanity's Last Exam 점수를 제시했다. Opus 5.5가 67.7%, GPT-6 Astra가 57.2%로, 이는 제조사가 직접 보고한 수치다 ([Claude Opus 5.5 소개](https://www.anthropic.com/claude-opus-5-5)). Anthropic의 재현 쿡북은 제3자 평가가 "하네스 구성 때문에 흔히 더 낮게 나온다"고 적고 있다 ([Claude 쿡북](https://platform.claude.com/cookbook/evals-agentic-search-reproduce-agentic-search-benchmarks)).

체감 열세의 더 직접적인 원인은 도구 설계에 있다. Claude Code의 `WebSearch`는 검색 결과의 제목과 URL만 돌려주고 페이지를 가져오지 않는다. 검색 백엔드도 바꿀 수 없어서 다른 검색 엔진을 쓰려면 MCP 서버를 붙여야 한다. Bedrock에서는 서버 측 웹 검색 자체가 제공되지 않는다 ([Claude Code 도구 레퍼런스](https://code.claude.com/docs/en/tools-reference)). API의 웹 검색 도구는 상황이 다르다. 2026년 버전(`web_search_20260209` 이후)은 Claude가 코드로 결과를 걸러 낸 뒤에야 맥락에 넣는 동적 필터링을 지원하고, `user_location`으로 국가를 지정할 수 있다. 요금은 OpenAI와 같은 1,000회당 $10이다 ([웹 검색 도구](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)). 수업 사이트에서는 검색이 아예 교체 가능한 부품이 된다. Brave는 1,000회당 약 $5, Exa는 약 $7, Perplexity Search는 약 $5다 ([beri.net 비교](https://www.beri.net/article/tavily-vs-exa-vs-brave-vs-perplexity-search-api-agent-cost-2026)). Open WebUI는 약 28개의 검색 백엔드를 플랫폼 차원에서 붙일 수 있다 ([Open WebUI 웹 검색](https://docs.openwebui.com/features/chat-conversations/web-search)). 한 가지 공백은 남는다. 한국어 질의의 검색 품질을 비교한 벤치마크는 찾지 못했다. 국내 자료 검색이 중요한 수업이라면 파일럿 기간에 검색 공급자 두세 곳을 직접 비교해 봐야 한다.

표가 보여 주는 패턴은 분명하다. 프롬프트 수준의 기록을 볼 수 있는 곳은 **기관이 관리하는 등급뿐이다.** 그리고 그 권한은 교수자가 아니라 IT 관리자나 워크스페이스 소유자가 컴플라이언스와 eDiscovery 용도로 갖는다. Claude for Education 관련 2025년 발표는 대화가 "기본적으로 비공개"이고 기관이 데이터를 요청하려면 공식 승인이 필요하다고 밝혔다 ([Anthropic](https://www.anthropic.com/news/advancing-claude-for-education)). ChatGPT Edu의 "대화 메시지" 권한은 워크스페이스 소유자만 부여할 수 있다 ([OpenAI 도움말](https://help.openai.com/en/articles/9261474-openai-compliance-platform-for-enterprise-and-edu-customers)). Google Vault는 2026년 6월 Gemini 앱 대화의 보존 규칙과 소송 보존을 지원하기 시작했고, 10월에는 필터링 내보내기를 추가했다. 대화 기록 보존 기간은 관리자가 3·18·36개월 중에서 정하며 기본값은 18개월이다 ([Workspace 업데이트](https://workspaceupdates.googleblog.com/2026/10/google-vault-now-supports-filtered-exports-for-Gemini-in-Workspace.html); [Workspace 도움말](https://knowledge.workspace.google.com/admin/generative-ai/workspace-with-gemini/manage-gemini-in-workspace-conversation-history-settings)). 이런 도구를 일상적인 학습 지도나 채점에 쓰려면 대학 차원의 정책과 학생 고지가 필요하다. 반대로 교수자가 혼자 살 수 있는 등급은 Claude Team, ChatGPT Business, 학생용 무료 혜택 모두 교수자에게 학생 기록을 보여 주지 않는다. 40명분 Team 좌석은 월 $1,000이다(40석 × $25). 그 돈을 내도 학생 대화는 볼 수 없다.

Copilot Student의 신규 가입이 현재 열려 있는지는 자료마다 엇갈린다 ([chalkbox](https://www.chalkbox.org/guides/github-copilot-student/)). 이런 개인 혜택을 쓰는 학생에 대해서는 공유 링크나 GitHub Classroom 커밋을 과제와 함께 제출받는 '제출 기반 열람'이 유일한 합법적 확인 수단이다.

## 40명 한 학기 비용은 대화형 ₩40만, 실습형 ₩170만~350만

비용 추정의 가정은 다음과 같다. 학생 40명, 주 2회 수업, 15주로 학생-세션은 한 학기 1,200회, 월 약 346회다. 환율은 2026년 10월 21일 종가 ₩1,325를 반올림한 ₩1,330을 적용했다 ([Investing.com](https://kr.investing.com/currencies/usd-krw-historical-data)). 가격은 Anthropic 공식 요금표를 썼다. Haiku 5.5는 입력 $0.10, 출력 $0.50(프롬프트 10만 토큰 이하 기준), Sonnet 5.5는 $2/$10에 캐시 읽기 $0.10, Opus 5.5는 $4/$20이다 ([Claude 가격](https://platform.claude.com/docs/en/about-claude/pricing)). 세션 유형은 넷이다. 대화형(A)은 20턴에 입력 약 15.7만, 출력 1.4만 토큰이다. 검색 포함 대화(B)는 세션당 검색 10회로, 지난 검색 결과를 계속 들고 가면 입력이 약 107만 토큰, 결과를 정리하는 B-lean이면 약 26만 토큰이다. 에이전트 코딩(C)은 입력 200만, 출력 5만 토큰이다. 모두 개발자 데이터를 바탕으로 만든 모델링 값이고, 학생을 실측한 값이 아니다.

| 시나리오 (40명, 15주 한 학기 합계) | Haiku 5.5 | Sonnet 5.5 | Opus 5.5 |
|---|---|---|---|
| A. 가벼운 대화 | $16 (₩2만) | **$299 (₩40만)** | $599 (₩80만) |
| B-lean. 대화와 검색 10회, 지난 결과 정리 | $142 | $528 (₩70만) | $936 |
| B. 대화와 검색 10회, 결과 누적 | $164 | $896 (₩119만) | $1,672 |
| 혼합 (A 60%, B 25%, C 15%) | $62 | **$599 (₩80만)** | $1,168 (₩155만) |
| C. 매 수업 에이전트 코딩 | $76 | **$1,301 (₩173만)** | $2,602 (₩346만) |
| D. 고강도 에이전트 (입력 600만 토큰) | $523 | $3,542 (₩471만) | $7,085 (₩942만) |

혼합 행을 뺀 나머지는 모든 수업 세션이 그 유형이라고 가정한 값이다. 30명이면 0.75배, 50명이면 1.25배로 환산하면 된다. 학생 한 명당으로 나누면 Sonnet 대화형이 한 학기 $7.50, 에이전트 코딩이 $33이다. 학생 한 명이 Claude Pro를 4개월 구독하는 비용($80)과 비교하면 대화형 수업의 API 비용은 그 10분의 1도 되지 않는다. 다른 회사 모델과 비교해 보자. GPT-6 Sol은 Sonnet 5.5와 표시 가격($2/$10)이 같지만 캐시 읽기가 $0.20으로 두 배다. 그래서 캐시가 많이 쓰이는 에이전트 시나리오에서는 $1,522로 Sonnet보다 비싸진다 ([GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol)). 최상위 모델끼리 보면 Opus 5.5가 GPT-6 Astra($10/$50)보다 2.5배 싸다 ([GPT-6 Astra](https://developers.openai.com/api/docs/models/gpt-6-astra)). Gemini 3.8 Flash는 2026년 12월 31일까지 $0.75/$3.75의 도입가를 적용하고 2027년 1월 1일부터 두 배로 올린다. 따라서 2027년 봄학기 예산은 인상 후 가격으로 잡아야 한다 ([Gemini 가격](https://ai.google.dev/gemini-api/docs/pricing)). OpenAI와 Google 가격은 공식 페이지를 직접 열지 못하고 검색 발췌로 확인했다.

Max 크레딧이 어디까지 감당하는지는 월 단위로 따져야 한다. 40명 기준 월 비용은 Sonnet 대화형이 $86, B-lean이 $152로, Max 20x의 $200 안에 들어간다. Sonnet 대화형은 Max 5x의 $100로도 충당된다. 반면 Sonnet 에이전트 코딩은 월 $376으로 $176가 모자라고, Opus 에이전트 코딩은 월 $751로 $551가 모자란다. 다르게 말하면 $200로 살 수 있는 세션은 Sonnet 대화형 약 800회, 검색 대화 268회, 에이전트 185회다. 수업에 필요한 세션은 월 약 346회다. 한 가지 운영상 함정이 있다. 크레딧이 $200인 조직은 최소 Start 등급이 되는데, **Start 등급의 월 지출 상한은 $500**이다. 상한에 닿으면 다음 달 1일(UTC)까지 HTTP 429 오류로 요청이 막힌다 ([Claude 요금 한도](https://platform.claude.com/docs/en/api/rate-limits); [API 크레딧 문서](https://platform.claude.com/docs/en/about-claude/api-credits-for-subscribers)). Opus로 에이전트 실습을 하는 수업이라면 학기 중간에 사이트가 멈출 수 있으므로 Build 등급($1,000)을 미리 요청해야 한다.

비용을 낮추는 수단은 효과가 큰 순서로 셋이다. 첫째, 기본 모델을 Haiku로 두는 것이다. 중간 등급 대비 15~20배가 절감된다. 둘째, 프롬프트 캐싱이다. 캐싱 없이 Sonnet 에이전트 세션을 돌리면 $4.50인데, 캐싱을 쓰면 $1.08이다. 셋째, 지난 검색 결과를 정리하는 것으로 약 40%가 절감된다. 검색 수수료 자체는 월 약 3,460회, $35 수준으로 작다. 검색 결과 토큰이 이후 턴마다 다시 전송되는 비용이 더 크다. 통제 장치는 Anthropic 쪽에서 수업 전용 워크스페이스에 월 지출 한도와 임계치 알림을 걸 수 있다 ([Workspaces](https://platform.claude.com/docs/en/manage-claude/workspaces)). OpenAI는 프로젝트 단위로 하드 리밋을 걸면 429로 차단한다 ([OpenAI 지출 한도](https://developers.openai.com/api/docs/guides/spend-limits)). 이 수치들에는 부가가치세와 카드 환전 수수료가 빠져 있다. 한국어 토큰화 비율도 측정된 자료가 없다. 첫 1~2주 파일럿에서 `usage` 필드로 실측해 보정해야 한다.

| LibreChat v0.8.8 | MIT | **앱 안에 열람 화면 없음**. Langfuse나 MongoDB로 조회 | **사용자별 크레딧 잔액**과 자동 충전 | Anthropic 네이티브 엔드포인트 |
| AnythingLLM | MIT | 워크스페이스·사용자별 채팅 로그, CSV/JSON 내보내기 | 사용자별 일일 메시지 한도 | Google OAuth 미지원 |
| Dify | 수정 Apache 2.0 | 앱별 로그 탭(원문 프롬프트, 도구 단계) | 확인 안 됨 | 멀티테넌트 운영과 로고 제거 금지 |
| Gen-Ed / CodeHelp | AGPL-3.0 | 교수자 역할, 수업 데이터 CSV 내보내기 | 확인 안 됨 | 정답 코드를 주지 않는 튜터 |
| LiteLLM (게이트웨이) | MIT 코어 | `store_prompts_in_spend_logs` 설정 시 열람 가능 | **학생별 예산·속도 제한** | 어떤 UI 앞에도 둘 수 있음 |

교수자의 핵심 요구에 기본 상태로 가장 가까운 것은 Open WebUI다. `ENABLE_ADMIN_CHAT_ACCESS`의 기본값이 True여서 관리자가 어느 사용자의 대화든 읽기 전용으로 열 수 있다 ([Open WebUI 환경 설정](https://docs.openwebui.com/reference/env-configuration#enable_admin_chat_access)). 분석 탭은 사용자·모델·그룹별 토큰 사용량을 보여 주고, 문서에도 "고사용자 식별"을 용도로 적어 두었다 ([분석 문서](https://docs.openwebui.com/features/administration/analytics)). 학생이 기록을 지우거나 피해 가지 못하게 하려면 `USER_PERMISSIONS_CHAT_DELETE=False`와 `USER_PERMISSIONS_CHAT_TEMPORARY=False`로 삭제와 임시 채팅을 막는다. 감사 로그는 `AUDIT_LOG_LEVEL=REQUEST_RESPONSE`로 켠다 ([환경 설정](https://docs.openwebui.com/reference/env-configuration#user_permissions_chat_delete); [감사 로그](https://docs.openwebui.com/reference/env-configuration#audit_log_level)). 가입 통제도 갖춰져 있다. 기본 역할이 관리자 승인을 기다리는 `pending`이고, Google OAuth를 `OAUTH_ALLOWED_DOMAINS`로 학교 도메인에 한정할 수 있다 ([기본 역할](https://docs.openwebui.com/reference/env-configuration#default_user_role); [SSO](https://docs.openwebui.com/features/authentication-access/auth/sso)).

주의할 점은 셋이다. 첫째, 서브에이전트나 타이머로 생긴 '내부 채팅'은 관리자 목록에 나타나지 않는다. 문서도 이런 기능을 쓸 때는 목록을 완전한 기록으로 간주하지 말라고 경고한다 ([환경 설정](https://docs.openwebui.com/reference/env-configuration#enable_admin_chat_access)). 둘째, 학생별 비용 한도는 Filter Function을 직접 만들거나 게이트웨이를 앞에 둬야 한다 ([Filter Functions](https://docs.openwebui.com/features/extensibility/plugin/functions/filter)). 셋째, 비용에 직접 영향을 주는 문제다. Open WebUI는 Anthropic을 OpenAI 호환 엔드포인트로 연결하는데, Anthropic은 이 엔드포인트를 "평가와 테스트용이지 프로덕션용이 아니다"라고 설명한다. 이 경로에서는 프롬프트 캐싱 같은 네이티브 기능을 쓸 수 없다 ([Open WebUI의 Anthropic 설정](https://docs.openwebui.com/getting-started/quick-start/connect-a-provider/starting-with-anthropic)). 캐싱이 가장 큰 비용 절감 수단이라는 점을 생각하면 LiteLLM을 앞에 두는 구성이 합리적이다. 다만 그 구성에서 캐싱이 실제로 적용되는지는 파일럿 때 `usage` 필드로 확인해야 한다. LiteLLM은 사용자마다 키를 만들 필요 없이 '고객' 단위로 `max_budget`과 `budget_duration`을 걸 수 있다 ([LiteLLM 예산](https://docs.litellm.ai/docs/proxy/users)). Open WebUI의 `ENABLE_FORWARD_USER_INFO_HEADERS`로 학생 신원을 넘겨받으면 된다. 학생 식별은 사용자명이 아니라 이메일로 해야 한다. 사용자는 자기 사용자명을 바꿀 수 있기 때문이다 ([LiteLLM × Open WebUI](https://docs.litellm.ai/docs/tutorials/openweb_ui)). 프롬프트 기록 옵션인 `store_prompts_in_spend_logs`는 기본값이 false이고, `maximum_spend_logs_retention_period`로 자동 파기 기간을 정할 수 있다 ([LiteLLM 설정](https://docs.litellm.ai/docs/proxy/config_settings)). 라이선스는 걱정할 필요가 없다. 브랜딩 조항은 최근 30일 사용자가 50명을 넘는 배포에서 'Open WebUI' 표시를 **지우거나 바꿀 때만** 적용된다. 문서도 교육용 사용을 허용한다고 명시한다 ([LICENSE](https://github.com/open-webui/open-webui/blob/main/LICENSE); [라이선스 문서](https://docs.openwebui.com/license)).

다른 선택지들은 각각 한쪽이 강하고 다른 쪽이 약하다. LibreChat은 MIT 라이선스이고, 사용자별 크레딧 잔액 기능이 가장 잘 갖춰져 있다. 1,000크레딧이 $0.001이므로 학생당 월 $5 한도는 500만 크레딧에 해당한다 ([LibreChat 잔액](https://www.librechat.ai/docs/configuration/librechat_yaml/object_structure/balance)). 그러나 관리자 패널의 API에는 대화를 읽는 엔드포인트가 없다. Insights도 최근 에이전트 대화의 첫 메시지만 보여 준다 ([관리자 패널](https://www.librechat.ai/docs/features/admin_panel); [Insights](https://www.librechat.ai/docs/features/insights)). 전체 기록을 보려면 Langfuse를 연동해야 한다 ([LibreChat Langfuse](https://www.librechat.ai/docs/configuration/langfuse)). AnythingLLM은 사용자별 채팅 로그를 기본으로 보여 주지만 Google OAuth가 없다 ([AnythingLLM 채팅 로그](https://docs.anythingllm.com/features/chat-logs)). 프로그래밍 수업이라면 Gen-Ed/CodeHelp를 함께 쓸 만하다. 교수자와 학생 역할, LTI 연동, CSV 내보내기를 갖췄다 ([Gen-Ed](https://github.com/liffiton/Gen-Ed)). 원 연구에서는 학생 52명이 12주간 사용했고 ([CodeHelp 논문](https://arxiv.org/abs/2308.06921)), 2,600건 이상의 질의에 약 $10이 들었다 ([일리노이 워크숍 자료](https://teaching-workshop.cs.illinois.edu/files/2023/06/2023-IL-CS-Summer-Teaching-Workshop-CodeHelp.pdf)). 절대로 하지 말아야 할 연결도 있다. LiteLLM의 `chatgpt/` 공급자는 ChatGPT 구독을 OAuth로 연결하는 기능이다 ([LiteLLM ChatGPT 공급자](https://docs.litellm.ai/docs/providers/chatgpt)). 이것을 수업에 쓰면 1장에서 다룬 공유 금지에 그대로 걸린다.

### 로그를 쌓는 순간 교수자에게 개인정보처리자의 의무가 생긴다

학생 계정에 묶어 프롬프트와 출력을 저장하면 개인정보보호법상 개인정보 처리가 된다. 이 자료를 미국의 Anthropic이나 OpenAI API로 보내는 것은 국외 이전 또는 처리위탁에 해당한다. 제28조의8은 국외 이전의 근거로 별도 동의를 받거나, 처리방침에 이전받는 국가, 시기와 방법, 받는 자, 목적과 보유기간, 거부 방법과 그 효과를 공개하는 등의 요건을 정한다. 동의를 근거로 삼는 경우에는 처리방침 공개만으로 동의를 대신할 수 없다는 해설도 있다 ([로톡 해설](https://www.lawtalk.co.kr/posts/85853); [ISMS-P 3.3.4](https://itwiki.kr/w/ISMS-P_%EC%9D%B8%EC%A6%9D_%EA%B8%B0%EC%A4%80_3.3.4.%EA%B0%9C%EC%9D%B8%EC%A0%95%EB%B3%B4%EC%9D%98_%EA%B5%AD%EC%99%B8%EC%9D%B4%EC%A0%84)). 개인정보보호위원회의 관련 지침도 잇따랐다. 2025년 8월 '생성형 AI 개발·활용을 위한 개인정보 처리 안내서'를 냈다 ([디지털데일리](https://www.ddaily.co.kr/page/view/2025080611120338544)). 2026년 4월에는 처리방침 작성지침에 생성형 AI 부록을 추가해, 이용자가 입력한 텍스트와 파일을 수집·저장하는지, 학습에 쓰는지, 어떻게 거부할 수 있는지를 적도록 했다 ([뉴시스](https://mobile.newsis.com/view/NISX20260424_0003604909)). 2026년 5월에는 이용자용 가이드도 나왔다 ([바이라인네트워크](https://byline.network/2026/05/19-618/)). 법령 원문과 위원회 원문은 이번 조사에서 직접 열지 못했고 2차 해설로 확인했다. 따라서 아래 절차는 법률 자문이 아니라 실무 체크리스트로 읽어야 한다.

첫 수업에서는 서면 고지와 동의서를 받는다. 동의서에는 목적(학습 지원과 평가), 수집 항목(이메일, 프롬프트, 출력, 시각, 토큰 사용량), 열람자(교수자와 조교), 보존 기간(예: 성적 확정 후 N개월), 국외 이전받는 자(Anthropic, OpenAI 등)를 적는다. 성적이 걸린 관계에서 동의가 진정으로 자유로우려면 AI를 쓰지 않고도 과제를 수행할 수 있는 대안을 함께 제시해야 한다. 보존 기간은 기술적으로도 집행해야 한다. Open WebUI에는 자동 만료 설정이 없어 스크립트로 지워야 한다. LibreChat은 `retentionMode: "all"`과 `generalChatRetention`으로, LiteLLM은 보존 기간 설정으로 처리할 수 있다 ([LibreChat 보존](https://www.librechat.ai/docs/features/temporary_chat)). Managed Agents와 OpenAI Agents API는 ZDR 대상이 아니어서 세션이 사업자 쪽에 남는다. 학기 말에 API로 삭제해야 한다 ([Managed Agents 개요](https://platform.claude.com/docs/en/managed-agents/overview)). 학생들에게는 타인의 개인정보나 민감정보를 입력하지 말라고 안내한다. 로그를 연구에 쓸 계획이 있으면 IRB 대상인지 확인한다. 국립대라면 공공기관으로서 추가 의무가 있는지 학교 개인정보 담당 부서와 상의해야 한다.

## 단계별 권고: Max 20x 크레딧과 Open WebUI로 시작하라

| 단계 | 시점 | 할 일 | 비용 |
|---|---|---|---|
| 0. 학교 자원 확인 | 2026년 11~12월 | Workspace for Education(Gemini와 Vault), M365 A 라이선스, ChatGPT Edu 도입 여부와 2027 공동구독 컨소시엄 참여 여부 확인. 개인정보 담당 부서와 협의 | 0원 |
| 1. 크레딧 확보 | 개강 4주 전 | Max 20x 유지 또는 가입, 7일 뒤 Console 조직 연결, 크레딧 약관 확인. 수업 전용 워크스페이스, 지출 한도, 50%·80% 알림 설정 | 월 $200 (₩26.6만) |
| 2. 사이트 구축 | 개강 2~3주 전 | Open WebUI(PostgreSQL)와 LiteLLM 구축. 학교 도메인 OAuth, `pending` 승인, 삭제·임시 채팅 금지, 감사 로그, 학생별 월 예산, 기본 모델 Haiku/Sonnet, 검색 공급자 선택 | 서버비(이번 조사에서 산정 안 함) |
| 3. 고지와 파일럿 | 1~2주차 | 동의서와 AI 사용 고지 배너, 비AI 대안 제시. 세션당 토큰, 캐시 적중률, 검색 횟수를 실측해 예산 보정 | 크레딧 안 |
| 4. 에이전트 실습 | 필요한 주차 | Managed Agents 위에 얇은 앱(같은 OAuth, 과제별 세션, 이벤트 DB). Codex가 필요하면 OpenAI API 키와 학생별 컨테이너의 `codex exec` | 시간당 $0.08에 토큰 비용 |
| 5. 종료와 파기 | 성적 확정 후 | 채점 근거를 보관한 뒤 보존 기간이 지나면 DB 로그, LiteLLM 로그, Managed Agents 세션 삭제 | 0원 |

출발점은 0단계다. 대학이 이미 Google Workspace for Education을 쓴다면 Gemini 앱과 NotebookLM이 무료이고 Vault 기록도 있다. 서울대처럼 ChatGPT Edu가 있는 학교라면 Codex까지 포함된다. 이런 학교에서는 사이트를 직접 만들기 전에 기관 도구에 공유 링크 제출을 결합하는 방안을 먼저 따져 볼 만하다. 공동구독 예산이 국회를 통과할지는 2026년 12월에 정해지므로 2027년 2학기부터는 판도가 달라질 수 있다. 학생들에게는 2026년 12월 31일 마감으로 보도된 Google AI Plus 무료 혜택을 개인용 보조 수단으로 안내해 둔다.

자체 사이트를 만든다면 1~3단계가 핵심이다. 핵심 숫자는 이렇다. $200 크레딧을 학생 40명에게 나누면 **학생당 월 $5**이고, 이 값을 LiteLLM의 학생별 `max_budget`에 그대로 넣으면 크레딧 범위 안에서 운영이 보장된다. 기본 모델은 Haiku 5.5나 Sonnet 5.5로 두고, Opus는 교수자가 그룹 단위로 허용한다. 검색은 턴당 2회로 제한하고, 지난 검색 결과는 정리한다. GPT 모델도 함께 제공하고 싶다면 OpenAI API 프로젝트를 따로 만들어 하드 리밋을 걸고 같은 LiteLLM 뒤에 붙인다. 교수자가 원래 쓰던 ChatGPT Plus는 개인 용도로만 남긴다.

4단계는 프로그래밍 실습처럼 실제로 에이전트가 필요한 주차에만 연다. Managed Agents를 쓰면 샌드박스 운영 부담이 사라지고, 서버 측 이벤트 기록이 그대로 학생별 열람 화면이 된다. 이 단계에서는 월 비용이 크레딧을 넘기 쉽다. 사전에 구매 크레딧과 자동 충전 한도를 정하고, Start 등급의 $500 상한을 넘을 것 같으면 Build 등급을 신청해 둔다. 하지 말아야 할 것은 이 모든 단계에서 같다. `claude -p`나 `setup-token`으로 만든 릴레이, CLIProxyAPI·sub2api 같은 구독 프록시, LiteLLM의 `chatgpt/` 공급자, ChatGPT 로그인 공유는 어느 단계에서도 쓰지 않는다.

## 결론

2026년 하반기에 바뀐 핵심은 Claude에서 '구독이냐 API냐'의 양자택일이 사라졌다는 점이다. Max 구독은 이제 개인 사용권과 월 $100~200의 API 바우처를 묶은 상품이 되었다. 그래서 구독을 먼저 쓰고 싶다는 교수자의 의도는 공유가 아니라 전환을 통해 합법적으로 이룰 수 있다. 다만 이 다리는 Anthropic에만 있다. OpenAI는 반대 방향으로 갔다. SIWC는 플랜을 '각 사용자가 자기 것으로 들고 다니는' 방식이어서, OpenAI 구독으로 가는 유일한 합법 경로는 학생 각자의 플랜이다. 수업 플랫폼을 고를 때 어느 모델이 똑똑한지보다 어느 회사의 과금 구조가 교수자 한 사람이 비용을 대는 형태와 맞는지가 더 중요해졌다.

두 번째로 주목할 점은 열람권의 역설이다. 가장 싼 자체 구축안이 수백만 원짜리 기관 플랜보다 교수자에게 더 많은 것을 보여 준다. 그 대가로 법적 책임도 교수자에게 옮겨 온다. 이제 결정적인 제약은 사업자 약관이 아니라 개인정보보호법과, 성적이 걸린 관계에서 받는 동의가 진정한 동의인가의 문제다. 앞으로 지켜볼 일정은 네 가지다. 11월 12일 AUP 시행, 크레딧 프로그램 약관의 세부 문구, 12월 공동구독 예산 확정, 2027년 1월 Gemini 가격 인상이다. 장기적으로는 SIWC가 원격 호스팅 앱에 열리고 대학이 Edu 좌석을 공급하게 되면, 학생 각자의 플랜으로 수업 사이트를 돌리는 세 번째 모델이 현실적인 선택지가 될 수 있다.
